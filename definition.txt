SECTION 7 — ONLINE MEMBER REGISTRATION & APPROVAL SYSTEM
======================================================


The site supports TWO ways to create a member:


--------------------------------------------------
METHOD 1 — Online Registration Request (register.php)
--------------------------------------------------
A visitor who is not yet a member fills out register.php. This
does NOT create a member account. It only creates a pending
request.


Form fields:
    • Full Name
    • Gender
    • Date of Birth
    • Phone Number
    • Email Address
    • Address
    • Emergency Contact
    • Preferred Membership Plan (Standard / Premium / Elite)
    • Membership Duration (1 / 3 / 6 / 12 Months)
    • Username
    • Password (with eye icon toggle)


On submit:
    • Insert the row into the `requested_members` table with
      status = 'Pending'.
    • Show the visitor a confirmation message:
          "Your membership request has been submitted successfully.
          Our team will contact you shortly."
    • No account is active yet. The submitted username/password
      cannot log in until approved.


--------------------------------------------------
ADMIN SIDE — Managing Registration Requests
--------------------------------------------------
Sidebar item: Requests -> Registration Requests
(admin/request/registration_request/requests.php)


Dashboard summary card: "Pending Registration Requests" with a live
count.


List page columns:
    Request ID | Full Name | Phone | Email | Selected Plan |
    Selected Duration | Request Date | Status | Action


Action buttons: View, Approve, Reject.


View Request page shows every field submitted by the visitor
(photo optional, full name, gender, DOB, phone, email, address,
emergency contact, selected plan, selected duration, username,
request date, status).


Approve Request:
    1. Copy all matching fields from `requested_members` into the
       `members` table.
    2. Automatically calculate:
           membership_start_date = today's date
           membership_expiry_date = start date + selected duration
    3. Set members.status = 'Active'.
    4. Record approved_date and approved_by (admin id) on the
       request row.
    5. Update the request's status to 'Approved' (keep the row for
       history instead of deleting it).
    6. members.created_method = 'Request'.
    7. The visitor can now log in successfully with the username/
       password they chose.


Reject Request:
    • Set the request status to 'Rejected'. Keep it stored for
      history. A rejected request cannot log in and does not
      create a member row.


--------------------------------------------------
METHOD 2 — Admin Direct Add (admin/member/add-member.php)
--------------------------------------------------
The admin can also create a member manually at any time, without
any request/approval step. Filling and saving the Add Member form
inserts directly into `members` with created_method = 'Admin' and
status = 'Active' immediately. Both methods must ultimately produce
the exact same shape of row in the `members` table — only the
`created_method` value differs.


--------------------------------------------------
Login Rule
--------------------------------------------------
Only rows inside `members` with status = 'Active' can log in.
Rows inside `requested_members` (regardless of status) can never
log in directly — they must first be approved by the admin.

SECTION 9 — TRAINER & BATCH MANAGEMENT SYSTEM
======================================================


Recommended build order (keeps the database and logic simple):
    Step 1: Admin adds Trainers.
    Step 2: Admin creates Batches and assigns one or more trainers
            to each batch.
    Step 3: Admin adds a Member and assigns that member a
            Membership Plan + a Batch (the batch already carries a
            fixed time and trainer, so there is no separate "select
            time" field needed on the member form).


--------------------------------------------------
Trainer Management (admin/trainer/)
--------------------------------------------------
Add Trainer fields:
    Trainer ID (Auto) | Full Name | Gender | Date of Birth |
    Phone Number | Email | Address | Specialization
    (e.g. Yoga, Cardio, Strength Training, Zumba, Group Workout) |
    Salary | Joining Date | Status (Active/Inactive) | Photo


Trainer List columns:
    Trainer ID | Photo | Name | Specialization | Shift | Status |
    Action (View / Edit / Delete)


Edit Trainer: admin may update phone, address, specialization,
salary, shift, and status.


Delete Trainer rule:
    Before deleting, check whether the trainer is assigned to any
    batch (via batch_trainers). If assigned, block the deletion
    and show:
        "Cannot delete trainer. This trainer is assigned to active
        batches. Please reassign or remove the trainer from those
        batches first."


View Trainer Details shows: name, specialization, status, list of
assigned batches with their time, and total member count across
those batches.


--------------------------------------------------
Batch Management (admin/batch/)
--------------------------------------------------
Batch Management means creating gym class "batches" (think of it
like a school timetable). Each batch has:
    Activity | Trainer(s) | Time | Maximum Members | Assigned
    Members


Add Batch fields:
    Batch Name | Activity | Trainer (selected from the existing
    Trainer list — trainer's specialization should match the
    batch's activity) | Start Time | End Time | Maximum Members |
    Description | Status


Batch List columns:
    Batch | Activity | Trainer | Time | Members (e.g. "18/20")


Batch Details (view-batch.php) shows batch name, trainer(s),
activity, time, and the full list of assigned members.


Assignment Rules (must be enforced with validation, not just UI):
    Rule 1 — One trainer CAN handle many batches (e.g. Priya can
             teach Morning Yoga at 6 AM and Evening Yoga at 5 PM).
             Allowed.
    Rule 2 — One trainer CANNOT handle two batches scheduled at the
             exact same time. Not allowed.
    Rule 3 — One member CANNOT join two batches scheduled at the
             exact same time. Not allowed.
    Rule 4 — One batch cannot exceed its maximum member capacity.
             If Max = 20 and 20 are already assigned, block adding
             a 21st member to that batch.
    Rule 5 — A member whose membership status is Expired cannot be
             newly assigned to (or continue attending) a batch
             until their membership is renewed and Active again.


--------------------------------------------------
How a Member Gets a Batch
--------------------------------------------------
On the Add Member form (admin) and on the Registration Request
form (public), the Batch is selected from a dropdown populated from
the batches table (only Active batches, filtered so full batches
are visibly marked or disabled). Selecting a batch automatically
implies its trainer(s) and time — no separate time field is shown.
